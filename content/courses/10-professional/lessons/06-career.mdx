## Web開発者のキャリアパス

Web開発者には主に3つの方向性があります：

```
Web開発者
├── フロントエンドエンジニア
│   → UI/UXに特化・React/Vue・デザインシステム
│
├── バックエンドエンジニア
│   → API・DB・サーバーサイド・スケーリング
│
├── フルスタックエンジニア（最もよくある進路）
│   → フロント/バックエンド両方・個人開発や小〜中規模チームに多い
│
└── 専門職
    ├── セキュリティエンジニア
    ├── インフラ/SREエンジニア
    ├── データエンジニア
    └── テックリード/エンジニアリングマネージャー
```

## スキルレベルの目安

### ジュニア（〜2年）
- HTML/CSS/JavaScriptの基礎
- React（またはVue/Angular）の基本的な使い方
- Git・GitHubでのPR
- シンプルなREST APIの作成
- 指示を受けて実装できる

### ミドル（2〜5年）
- TypeScriptを実務レベルで使える
- テストを書ける（ユニット・統合）
- コードレビューができる
- パフォーマンスとセキュリティを意識した実装
- 設計について議論できる

### シニア（5年〜）
- システム設計・アーキテクチャ判断
- チームの技術的課題を解決できる
- 他のメンバーの成長を支援できる
- 技術選定に責任を持てる
- ビジネス要件を技術仕様に変換できる

## ポートフォリオの作り方

採用担当者は「実際に動くもの」を見ます：

```markdown
## 良いポートフォリオの条件

1. 実際にデプロイされている（Vercel等で公開）
2. README.mdが充実している
   - 何が作れるアプリか
   - 技術スタック
   - セットアップ方法
   - スクリーンショット
3. コードが読める
   - TypeScriptを使っている
   - コミット履歴が整理されている
4. 認証・DB・APIなど実務的な機能を含む

## ポートフォリオアイデア
- タスク管理アプリ（CRUD + 認証）
- ブログシステム（MDX + Next.js）
- 家計簿アプリ（グラフ・DB）
- お気に入り音楽共有（Spotify API）
```

## 継続的な学習

```markdown
## 日常的な学習習慣

### 技術ブログ・ニュース
- Zenn・Qiita（日本語の技術記事）
- dev.to（英語）
- Hacker News（最新トレンド）
- 各フレームワークの公式ブログ（Next.js, React等）

### OSS貢献
- ドキュメントの修正から始める
- Issue対応・小さなバグ修正
- 自作ライブラリを公開する

### アウトプット
- 学んだことをブログに書く（Zenn等）
- 勉強会・カンファレンスで登壇
- X（Twitter）で技術情報を発信
```

## 転職・就職活動

```markdown
## 技術面接の準備

### コーディングテスト
- LeetCodeのEasy/Medium問題を練習
- データ構造（配列・ハッシュマップ・木）を理解
- 時間計算量（O(n)・O(log n)）を説明できる

### システム設計面接
- 「Twitterのタイムラインを設計してください」等の質問
- スケーラビリティ・可用性・一貫性のトレードオフを考える
- DBの設計・キャッシュ・ロードバランサーを説明できる

### 行動面接
- STAR法（Situation・Task・Action・Result）で回答
- 過去の困難な経験とどう乗り越えたか
- チームでの協力・対立の解決経験
```

<Callout type="tip" title="アウトプットが最速の成長">
学んだことをブログに書くと「分かったつもりだった」部分が明確になり、理解が深まります。また、ブログがポートフォリオになり転職でも評価されます。完璧でなくていい、「今日学んだこと」を書き続けましょう。
</Callout>

## まとめ

- フロント・バックエンド・フルスタックのキャリアパスがある
- ジュニア→ミドル→シニアはスキルの深さと設計・チームへの貢献で変わる
- ポートフォリオは実際に動くものをデプロイして公開する
- ブログ・OSS・勉強会のアウトプットが成長を加速する
- 転職活動はコーディングテスト・設計面接・行動面接の準備をする
