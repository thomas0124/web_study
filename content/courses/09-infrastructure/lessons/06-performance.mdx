## なぜパフォーマンスが重要か

- **SEO**: Googleはページ表示速度をランキング要素に使う
- **UX**: 100ms遅くなるごとにコンバージョン率が1%下がる（Amazon調査）
- **モバイル**: 低速回線・低性能端末のユーザーへの配慮

## Core Web Vitals

Googleが定義するWebパフォーマンスの主要指標：

| 指標 | 内容 | 良い値 |
|-----|------|-------|
| **LCP** | Largest Contentful Paint（主要コンテンツ表示） | ≤2.5秒 |
| **FID/INP** | First Input Delay / Interaction to Next Paint | ≤100ms |
| **CLS** | Cumulative Layout Shift（レイアウトのずれ） | ≤0.1 |

```bash
# Lighthouseで計測
npx lighthouse https://example.com --output html --view
```

## 画像最適化

```jsx
// Next.jsのImageコンポーネント（自動最適化）
import Image from "next/image";

<Image
  src="/hero.jpg"
  alt="ヒーロー画像"
  width={1200}
  height={630}
  priority          // LCPの画像はpriority=trueに
  placeholder="blur" // 読み込み中にぼかし表示
/>
```

手動での最適化：

```bash
# WebPに変換（JPGより30-50%軽量）
cwebp hero.jpg -o hero.webp

# 適切なサイズにリサイズ（表示サイズより大きい画像は無駄）
convert hero.jpg -resize 1200x hero-1200.jpg
```

## キャッシュ戦略

### HTTPキャッシュ

```javascript
// Next.jsでキャッシュヘッダーを設定
export async function GET() {
  return Response.json(data, {
    headers: {
      // 1時間キャッシュ、その後はrevalidate
      "Cache-Control": "public, max-age=3600, stale-while-revalidate=86400",
    },
  });
}
```

### ISR（Incremental Static Regeneration）

```javascript
// app/products/[id]/page.tsx
export const revalidate = 3600; // 1時間ごとに再生成

export default async function ProductPage({ params }) {
  const product = await getProduct(params.id);
  return <Product data={product} />;
}
```

## メモ化

```jsx
import { memo, useCallback, useMemo } from "react";

// コンポーネントのメモ化（propsが変わらなければ再描画しない）
const ExpensiveList = memo(function ExpensiveList({ items }) {
  return items.map((item) => <Item key={item.id} {...item} />);
});

// 関数のメモ化（依存関係が変わらなければ同じ関数インスタンスを返す）
const handleClick = useCallback(() => {
  doSomething(id);
}, [id]);

// 値の計算をメモ化（依存関係が変わらなければ再計算しない）
const sortedItems = useMemo(() =>
  [...items].sort((a, b) => a.name.localeCompare(b.name)),
  [items]
);
```

<Callout type="info" title="計測なくして最適化なし">
パフォーマンス最適化は「感覚」でなく「計測」に基づいて行います。まずLighthouseやChrome DevToolsのPerformanceタブで現状を計測し、最もインパクトのある部分から手を付けましょう。早すぎる最適化はコードを複雑にするだけです。
</Callout>

## まとめ

- Core Web Vitals（LCP・INP・CLS）でパフォーマンスを指標化
- Next.jsのImageコンポーネントで画像を自動最適化
- バンドル分析で重いパッケージを特定してTree Shaking・遅延ロードで削減
- HTTPキャッシュとISRで再リクエストを減らす
- 計測して問題を特定してから最適化する
