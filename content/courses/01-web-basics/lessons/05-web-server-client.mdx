## クライアントとサーバー

Webの世界は基本的に**クライアント**と**サーバー**の2者が通信する構造です。

**クライアント（Client）**  
サービスを要求する側。Webブラウザが代表例。ユーザーが操作するデバイス上で動作します。

**サーバー（Server）**  
サービスを提供する側。データの保存・処理・配信を担当します。通常はクラウド上や専用のデータセンターで24時間稼働しています。

```
クライアント（ブラウザ）  ←→  Webサーバー
                                  ↕
                              データベース
```

## Webサーバーの役割

Webサーバーは主にHTTPリクエストを受け取り、レスポンスを返す役割を担います。

### 代表的なWebサーバーソフトウェア

| ソフトウェア | 特徴 | 用途 |
|------------|------|------|
| **Nginx** | 高速・軽量、静的ファイル配信が得意 | 大規模サービスに多用 |
| **Apache** | 歴史が長く機能豊富 | 汎用的なWebサーバー |
| **Node.js** | JavaScriptでサーバーを実装 | APIサーバーなど |

## 静的サイトと動的サイト

### 静的サイト（Static Site）

あらかじめHTMLファイルが作成されており、リクエストに対して毎回同じファイルを返します。

- **メリット**: 高速、シンプル、セキュリティリスクが低い
- **デメリット**: ユーザーごとに異なる内容を出せない
- **例**: 企業の説明ページ、ブログ、ドキュメントサイト

```
リクエスト → サーバー → 固定のHTMLファイル → レスポンス
```

### 動的サイト（Dynamic Site）

リクエストを受けてサーバーが処理を行い、その場でHTMLを生成して返します。

- **メリット**: ユーザーごとに異なる内容（マイページ、検索結果など）を表示できる
- **デメリット**: 処理が複雑、サーバーの負荷が高い
- **例**: ECサイト、SNS、メールサービス

```
リクエスト → サーバー → プログラム実行 → DB参照 → HTMLを生成 → レスポンス
```

## SSR・CSR・SSG

現代のWeb開発では、レンダリング方式がさらに細分化されています。

### CSR（Client Side Rendering）

JavaScriptがブラウザ上でHTMLを生成する方式。初回表示は遅いが、その後の操作は高速。ReactのSPA（Single Page Application）が代表例。

### SSR（Server Side Rendering）

サーバーがリクエストごとにHTMLを生成して返す方式。SEOに強く初回表示が速い。Next.jsのデフォルト動作。

### SSG（Static Site Generation）

ビルド時（デプロイ前）にHTMLを全ページ生成しておく方式。最も高速で安全。このWebサイトもSSGで作られています。

<Callout type="tip" title="どれを選ぶべきか">
- コンテンツが頻繁に変わらない → **SSG**
- ユーザーごとに異なるデータを扱う → **SSR**
- インタラクティブな操作が多い → **CSR**
- 大規模なサービスでは組み合わせることが多い
</Callout>

## APIサーバーとフロントエンドの分離

近年は「**フロントエンド（UI）**」と「**バックエンド（API）**」を分離する設計が主流です。

```
ブラウザ（React/Vue等）
     ↕ HTTP（JSON）
APIサーバー（Node.js/Python等）
     ↕ SQL/クエリ
データベース（MySQL/PostgreSQL等）
```

フロントエンドはAPIを通じてデータを取得・操作し、画面描画はブラウザが担当します。この設計をBFF（Backend For Frontend）や REST API アーキテクチャと呼びます。

## まとめ

- クライアントとサーバーがHTTPで通信するのがWebの基本
- 静的サイトはファイルをそのまま返し、動的サイトはサーバーで処理して返す
- CSR・SSR・SSGはそれぞれ適した用途がある
- フロントエンドとバックエンドの分離が現代の主流設計
