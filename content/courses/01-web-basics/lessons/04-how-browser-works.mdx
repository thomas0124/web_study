## URLを入力してから表示までの全体像

アドレスバーにURLを入力してEnterを押してから、画面にページが表示されるまでには、実は多くのステップがあります。

```
1. URLの解析
2. DNSによるIPアドレス解決
3. TCPコネクションの確立
4. HTTPリクエストの送信
5. HTMLの受信
6. HTMLのパース（解析）
7. CSSの適用
8. JavaScriptの実行
9. レンダリング（描画）
10. 表示完了
```

## ブラウザの主要コンポーネント

ブラウザは以下のコンポーネントで構成されています：

**レンダリングエンジン**  
HTMLとCSSを解析して画面に描画する中核部分。主要ブラウザのエンジン：
- Chrome/Edge: **Blink**
- Firefox: **Gecko**
- Safari: **WebKit**

**JavaScriptエンジン**  
JavaScriptコードを実行する部分。  
- Chrome: **V8**
- Firefox: **SpiderMonkey**
- Safari: **JavaScriptCore**

**ネットワーク層**  
HTTP通信を担当する部分。

**UIバックエンド**  
ウィンドウ・タブ・アドレスバーなどのUI部品を描画する。

## レンダリングの流れ

### 1. DOMツリーの構築

HTMLをパース（解析）して**DOM（Document Object Model）ツリー**を構築します。

```html
<html>
  <body>
    <h1>Hello</h1>
    <p>World</p>
  </body>
</html>
```

↓ パース ↓

```
Document
└── html
    └── body
        ├── h1 → "Hello"
        └── p  → "World"
```

### 2. CSSOMツリーの構築

CSSファイルを解析して**CSSOM（CSS Object Model）ツリー**を構築します。

### 3. レンダーツリーの構築

DOMツリーとCSSOMツリーを組み合わせて**レンダーツリー**を作ります。`display: none`の要素はここで除外されます。

### 4. レイアウト（リフロー）

各要素の位置とサイズを計算します。これを**レイアウト**または**リフロー**と呼びます。

### 5. ペイント（描画）

計算した位置・サイズに従い、実際に画面へ描画します。

<Callout type="warning" title="リフローのコスト">
JavaScriptでDOMを操作すると、レイアウト計算（リフロー）が再実行されます。リフローは処理コストが高いため、頻繁にDOMを変更するとパフォーマンスが低下します。変更をまとめて行うことが最適化の基本です。
</Callout>

## JavaScriptの実行タイミング

HTMLのパース中に`<script>`タグが見つかると、**デフォルトでは処理が停止**してJavaScriptのダウンロードと実行が完了するまで待ちます。

これを避けるため以下の属性が使われます：

```html
<!-- 非同期ダウンロード、ダウンロード完了後すぐ実行 -->
<script async src="script.js"></script>

<!-- 非同期ダウンロード、HTMLパース完了後に実行 -->
<script defer src="script.js"></script>
```

通常は`defer`を使うのがベストプラクティスです。

## Critical Rendering Path（重要レンダリングパス）

ブラウザが最初の描画を完了するまでの一連の処理を**Critical Rendering Path**と呼びます。この処理を最適化することがページの表示速度改善につながります。

主な最適化テクニック：
- CSSは`<head>`に配置（レンダリングブロックを減らす）
- JavaScriptは`defer`属性を使う
- 画像を遅延ロード（`loading="lazy"`）
- 不要なリソースを削減する

## まとめ

- ブラウザはURL解析からDNS・HTTP・レンダリングまで多くの処理を行う
- レンダリングエンジンがDOM・CSSOM・レンダーツリーを構築して描画する
- JavaScriptの実行タイミングはレンダリングに影響する
- Critical Rendering Pathの最適化がページ速度改善の鍵
