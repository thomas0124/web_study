### 3. エッジケース: 存在しないスラッグ → 404

コード検査で `notFound()` 呼び出しを確認：

| ファイル | 行 | パターン |

| `app/courses/[courseSlug]/page.tsx` | 28 | `if (!course) notFound();` |
| `app/courses/[courseSlug]/lessons/[lessonSlug]/page.tsx` | 31 | `if (!lesson) notFound();` |
| `app/courses/[courseSlug]/lessons/[lessonSlug]/page.tsx` | 34 | `if (!course) notFound();` |

`app/not-found.tsx` は存在し、日本語の 404 メッセージと「コース一覧へ戻る」リンクを含む。
ビルドログ内の `/_not-found` ルート生成でも確認済み。

`generateStaticParams()` が `getCourses()` / `getAllLessonPaths()` の全パスを列挙するため、
未定義スラッグは静的ルートに含まれず、Next.js の App Router の動的ルート漏れ落ち経路で
`notFound()` を通過してカスタム 404 が表示される。

## カバレッジギャップ

以下は今回テストできなかった振る舞い。プランのフォローアップとして推奨:

1. **`lib/content.ts` の自動化ユニットテスト未整備**
   - `getCourses()` の並び順（`meta.order` 昇順）が保証されているか
   - `getLesson()` の `prev` / `next` 計算が最初のレッスンで `prev = null`、
     最後のレッスンで `next = null` を返すか
   - 不正な frontmatter（`title` 欠落等）を持つ MDX に対する振る舞い
   - 修正推奨: `lib/content.test.ts` を Vitest で追加し、`scripts/test.local.sh` に
     `pnpm vitest run` を登録する

     手動確認またはヘッドレス E2E（Playwright 等）が必要
   - 現状はコード検査のみで代替

3. **モバイルレスポンシブ（プラン受け入れ基準の 375px 幅）**
   - 自動化されていない。将来的にビジュアルリグレッションまたは Playwright viewport
     テストを検討

4. **MDX 内のリンク切れ**
   - MDX 本文中に埋め込まれた相対リンクの整合性チェックはビルドで検知されない
